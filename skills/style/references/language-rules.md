# Language Rules

These rules are the detail behind the mandatory rules of the style skill. Apply them to all prose and to identifiers the repository creates.

## Scope

- Prose, headings, comments, and new identifiers use British English.
- Keep unchanged: existing identifiers, YAML keys (for example `artifacts`), library and API names, file paths, and quoted text.

## Dashes

- Never use the em dash character.
- Never substitute an en dash for an em dash.
- Replace an intended break with one of these:
  - a comma, for a short clause break;
  - a colon, to introduce an explanation or a list;
  - parentheses, for an aside.
- Ranges and compound words use a plain hyphen, for example 2026-10-18 or sign-in.

## Horizontal Dividers

- A divider is a line made only of three or more hyphens, asterisks, or underscores.
- Never use a divider in markdown bodies, chat replies, or reviews.
- Use a heading to separate sections.
- A table separator row (for example a row of hyphens between pipes) is part of the table, not a divider.
- YAML frontmatter delimiters are the only permitted delimiters.

## Examples

- Instead of an aside set off by dashes, write: "The gate passed (see the check output)."
- Instead of a break in a sentence, write: "The gate passed, so the sprint can close."
- Instead of a rule line between sections, write a new heading.
